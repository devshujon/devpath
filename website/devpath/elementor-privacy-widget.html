Privacy Policy

App: DevPath — Learn Code & Earn
Android package (production): com.devpath.dev
Effective date: 14 October 2026
Last updated: 19 October 2026
App version described: 1.3.1 (version code 16)

Summary: DevPath is built to work primarily offline. Most learning data stays on your device. DevPath does not operate a login or sync your progress to DevPath-operated servers in this version. Release builds may use Google AdMob, which can collect and process data under Google’s policies when ads are requested or shown. This app is not “child-safe” or “zero data collection” in the absolute sense—please read the sections below.

1. Who this policy applies to

This policy describes the DevPath mobile application for Android published under the package name com.devpath.dev. Debug builds distributed outside Google Play may use the package com.devpath.app.debug and Google’s test AdMob identifiers; behavior described here focuses on production release builds unless noted.

2. Information stored on your device

The app stores learning and app state locally, for example in SharedPreferences, app-private files, and (on startup) initialized Hive boxes. Depending on how you use DevPath, local data may include:

  • Completed lesson IDs, XP, levels, streaks, and learning minutes
  • Badges, achievements, challenges, and certificate progress
  • Playground drafts and user-saved editor projects
  • Mobile code editor workspace index and file contents under app-private storage
  • Notification preferences (reminder on/off, scheduled time)
  • Code editor settings (font size, theme, wrap, auto-save)
  • Ad-related timing metadata used to limit interstitial frequency (for example, timestamp of last interstitial)
  • Battery-optimization prompt state

This information is used to provide app functionality. DevPath’s application code does not upload this learning progress to DevPath-operated backend servers.

3. What DevPath does not do (in application code)

Based on the current open-source application code for version 1.3.1:

  • No DevPath user account, registration, or password system
  • No DevPath-operated analytics SDK (such as Firebase Analytics) in app dependencies
  • No dedicated crash-reporting SDK (such as Firebase Crashlytics or Sentry) in app dependencies
  • No sale of your personal data by DevPath through in-app code paths

Third-party libraries (especially ad networks) may still process data independently when their features run—see Section 8.

4. Network access and offline use

Android declares INTERNET and ACCESS_NETWORK_STATE. Bundled lessons and offline quizzes do not require network access. Network use may occur when:

  • Google Mobile Ads (AdMob) loads or serves advertisements in release builds
  • Embedded WebView components load local bundled assets for editor-related features; app code restricts navigation away from local/offline content in several WebView surfaces

The app does not include a general-purpose HTTP client for syncing your learning data to DevPath.

5. Google AdMob and advertising

Release builds embed a production AdMob App ID in the Android manifest and may show:

  • Banner ads on the home dashboard
  • Interstitial ads after certain quiz navigation (subject to a minimum interval stored locally)
  • Rewarded ads in quiz flows (for example optional retries or continues)

Debug builds replace the production App ID with Google’s test App ID and test ad units.

Advertising ID: The manifest declares com.google.android.gms.permission.AD_ID because the app depends on google_mobile_ads. Google may use the advertising ID or other device signals per Google’s policies and your device settings.

Personalization & consent: The app does not currently integrate Google’s User Messaging Platform (UMP) or another consent management platform. Ad requests use default AdRequest configuration in code. If you are in a region where consent is required for personalized ads (for example EEA/UK), the developer may need to implement consent before serving personalized ads at scale. You can limit ad personalization in your device’s advertising settings where Android provides them.

Recipients: Ad-related data processing is performed by Google and its ad partners as described in Google’s Privacy Policy and AdMob documentation.

DevPath has not verified ad serving, fill rates, or revenue in this document.

6. Permissions and optional features

Declared Android permissions include:

  • POST_NOTIFICATIONS — optional local learning reminders (Android 13+)
  • RECEIVE_BOOT_COMPLETED — reschedule local notifications after reboot
  • AD_ID — related to advertising as above

The app may ask you to allow notifications or to disable battery optimization so reminders fire on time. These use system settings and do not send your choices to DevPath servers.

File open & share: If you open or share files into DevPath, you choose the file via the system picker or intent. The app reads content you select for editing or preview. DevPath does not upload those files to DevPath servers in application code.

7. Device backup

Android backup may be enabled for the app (allowBackup with backup rules). Google or device manufacturer backup services may copy app-private data according to your system settings. DevPath does not control third-party backup providers.

8. Third-party SDKs (dependencies)

Key third-party components in the app include:

  • google_mobile_ads — advertising (see Section 5)
  • webview_flutter — embedded web content for some editor/curriculum surfaces
  • flutter_local_notifications — local scheduled notifications
  • permission_handler — runtime permission requests
  • file_picker, share_plus, path_provider, shared_preferences, hive — local storage and user-initiated sharing

Firebase: This project does not ship Firebase configuration (google-services.json) or Firebase SDKs in the current dependency set.

Third-party services may update their own data practices; refer to their documentation for retention and security.

9. Retention

  • On-device data remains until you clear app storage, uninstall, or restore from backup.
  • Ad partners may retain data according to their policies; DevPath does not control Google’s retention schedules.

10. Security

Local data is protected by Android app sandboxing. DevPath does not operate a user-facing server API for your progress in this version. No method of storage or transmission is 100% secure; use device lock screens and avoid sharing unlocked devices if your projects are sensitive.

11. Children’s privacy

DevPath is an educational coding app. It is not solely directed at children under 13, and the app does not provide a dedicated under-13 mode or parental gate in code. The app includes advertising in release builds, which may be subject to additional requirements for child-directed apps on Google Play and under laws such as COPPA (US) or similar regulations elsewhere.

Parents and guardians should supervise installation, permissions, backups, and ad exposure. If you believe a child provided personal information to a third-party ad service through the app, you may need to contact that provider (for example Google) as well as the developer using the contact methods in Section 13.

Your Google Play target audience and Families policy declarations are your responsibility as the publisher.

12. Your choices

  • Clear app data in Android Settings to remove most local DevPath state
  • Uninstall the app to remove the app from the device (backup copies may remain per Section 7)
  • Deny notification permission to disable reminders
  • Adjust personalized ads in Android advertising settings where available
  • Use debug builds with test ads only when testing (not representative of production ad behavior)

13. Contact & data requests

Developer contact (required for Play Console): A dedicated privacy or support email address is not published here yet. Before submitting com.devpath.dev to Google Play, the developer should add a reachable email address to this section and to the Play listing.

Developer profile: profiles.wordpress.org/devshujon

Optional channel (if the project repository is public): open an issue on the DevPath GitHub repository at github.com/devshujon/devpath/issues. Issues may be visible to others; do not post sensitive personal data publicly.

For data processed by Google Ads, you may also use Google’s ad settings and help resources. DevPath cannot delete Google-held ad data on your behalf.

No postal address or legal entity registration is listed in the app source code; add any required business identifiers here if your jurisdiction or Google Play requires them.

14. Changes to this policy

We may update this page when the app changes (for example new SDKs, ads, or data practices). The “Last updated” date at the top will change. The in-app copy bundled with your installed build may lag this web page until you update the app.

15. In-app access

You can also open a summary privacy policy inside the app from Profile → Privacy policy. The canonical public URL for store listings is:

https://devshujon.com/devpath/privacy-policy/
